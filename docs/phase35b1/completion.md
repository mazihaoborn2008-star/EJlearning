# Phase 3.5B.1 navigation hotfix

Scope is only navigation between Product UI V2 and the retained compatibility UI.

- Home’s secondary “继续原版学习” CTA is replaced with **探索词汇库**, linking to the V2 Vocabulary Library. The primary action still opens V2 Sentences.
- Every user-facing legacy entry is labeled **旧版学习（兼容）**, optionally followed by its purpose. Footer links remain secondary.
- All five legacy pages (Home, Learn, Progress, Placement, Checkpoint) receive a prominent sticky **返回新版学习** action on desktop and mobile, available even if the content API fails. The default HTML link works without JavaScript.
- Entering from V2 includes `?return=` with the current V2 route, filters and fragment. An explicit valid same-origin V2 URL is honored; absent or unsafe values return to `/`. External URLs, legacy loops and API destinations are rejected.
- Legacy link navigation preserves the return parameter. Same-tab legacy JavaScript transitions use a separate sessionStorage navigation preference. No learner key is read or written by the compatibility script. If storage is unavailable, explicit return URLs and ordinary link navigation still work.

The legacy wrapper is generated by `scripts/prepare-35b.js` from unchanged originals. Only the wrapper markup and new `legacy-navigation.js`/`.css` are added. Original `public/` files, Worker/API source, curriculum, migrations, learner engine, positioning, recommendations, academic and AI features are unchanged. **No D1 migration command is run.**

Navigation tests cover both directions at **360/390/430/1440 px**, all five legacy pages, default/contextual return, internal legacy navigation, keyboard activation, unsafe return rejection and storage failure. Screenshots and local/staging JSON evidence are in this directory.

Deployment target: existing **ej-learning-35b**, [isolated staging](https://ej-learning-35b.yanjian-language-learning.workers.dev). No resources are created, no custom route is attached, and production / Phase 3 / Phase 3.5A staging are not deployed or migrated.

`integrity-before.json`, `integrity-after.json` and `integrity-verification.json` verify protected environment equality and unchanged 3.5B D1 schema, migration history and content hashes (transient assessment sessions excluded). Old learning assets remain byte-identical after stripping the explicit compatibility wrapper from copied HTML.
